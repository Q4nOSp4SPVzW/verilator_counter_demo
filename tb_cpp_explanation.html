tb.cpp 解説

Verilator counter demo のC++テストベンチを、C++に詳しくない方向けに説明します。

1. このファイルの役割

tb.cpp は、Verilatorで変換された counter.sv をC++から動かすテストベンチです。 RTLに clk、rst、en を入れ、C++側で計算した期待値と RTLの count を毎サイクル比較します。

  1. RTLカウンタに入力信号を与える。
  2. C++側でも「正しいはずのcount」を計算する。
  3. RTLの count とC++の期待値を比較する。
  4. 違っていればFAILで停止する。
  5. 成功すればカバレッジと波形を保存する。

3. 期待値を持つScoreboard

このテストベンチの中心は Scoreboard です。 RTLとは別に、C++側で「次のcountはこうなるはず」という期待値を持ちます。 

struct Scoreboard {
    uint8_t expected = 0;

    void step(bool rst, bool en) {
        if (rst) {
            expected = 0;
        } else if (en) {
            expected = (expected + 1U) & 0x0fU;
        }
    }
};
条件期待値
rst=1count は0になる。
rst=0, en=0count は前回値を保持する。
rst=0, en=1count は1増える。
count=15, en=14bitなので0へ戻る。
& 0x0f は4bitに丸める処理です。 これにより、15の次は16ではなく0になります。

4. 1クロック進めるtick

static void tick(Vcounter* top, VerilatedVcdC* trace) {
    top->clk = 0;
    top->eval();
    trace->dump(sim_time++);

    top->clk = 1;
    top->eval();
    trace->dump(sim_time++);
}

top->clk を0から1へ動かして、RTLを1クロック進めます。 top->eval() は「今の入力でRTLを評価する」という命令です。 trace->dump() は、その時点の信号をVCD波形へ保存します。

5. 1サイクル分の処理

apply_cycle() が、毎サイクルの基本処理です。

  1. RTL入力に rst と en を入れる。
  2. 波形用に tb_test_id と tb_cycle_in_test を入れる。
  3. C++期待値を更新する。
  4. クロックを1回進める。
  5. RTLの count と期待値を比較する。
if (got != expected) {
    fail(test, cycle, got, expected);
}

値が違うと、どのテストの何サイクルで失敗したかを表示して停止します。

6. 各テストの意味

テスト確認していること
reset_test()rst=1 の間に count=0 になること、リセット解除後に保持されること。
hold_test()少しカウントした後、en=0 で値が止まること。
boundary_test()4bitカウンタが 15 -> 0 に戻る境界値動作。
reset_interrupt_test()カウント中に急に rst=1 を入れ、リセットが優先されること。
enable_toggle_test()en をON/OFFし、ONのときだけ増えること。
random_stress_test()1000サイクルのランダムな rst/en 入力でも期待値と一致すること。

ランダムテストは std::mt19937 を使い、シード値を 12345 に固定しています。 そのため、ランダムでも毎回同じ入力列になり、失敗時に再現できます。

7. main関数の流れ

  1. Verilatorを初期化する。
  2. Vcounter モデルを作る。
  3. VCD波形ファイル counter_trace.vcd を開く。
  4. 各テストを順番に実行する。
  5. 全部成功したら [PASS] all tests passed, checks=1060 を表示する。
  6. coverage.dat を保存する。
  7. 終了処理を行う。

checks=1060 は、1060回 count と期待値を比較したという意味です。

8. 波形用のテスト番号

tb_test_id と tb_cycle_in_test はRTLの機能には関係ありません。 GTKWaveで波形を見るとき、今どのテスト区間か分かるようにするための信号です。

9. まとめ

tb.cpp は、単に波形を出すだけのプログラムではありません。 C++側に期待値モデルを持ち、RTLの出力と毎サイクル比較する自動テストです。 そのうえで、カバレッジとVCD波形も保存するため、動作確認、未到達行の確認、波形確認をまとめて行えます。
